## 本轮交付记录

- H1：单控制任务独占官方播放器，最新请求覆盖旧请求，旧完成消息不能覆盖新状态；音乐/故事交接同样串行化。取消请求不等待，但官方阻塞调用返回前不能完成资源清理。
- H2：播放和上下个视频复用列表快照；返回列表按存储版本决定是否扫描。
- H3/H5：双暂存区交替准备与发送；视频整帧提交，退出视频后重新建立普通 UI 的差异比较镜像。
- H4：UI 借用有锁的最新帧直接画入画布，减少一次整帧复制并释放约 150 KiB 页面 PSRAM；增加约 5 KiB 内部 DMA 暂存和一个 8 KiB 控制任务栈。
- H6：新增 `sdkconfig.performance`，性能优化、保留断言，单独构建并检查 OTA 空间；不覆盖已有本地 sdkconfig。
- H7：按 I2S 背压及 4 ms 连续运行预算让出 CPU；新增纯解析长耗时、公平性和背压测试。
- H8：通过 USB 系统状态暴露各阶段耗时、首个后端画面、后端拷贝、LCD 实际提交次数/字节/耗时、普通音频解码/写入、控制任务栈余量。CPU 负载增加有效性标志；官方视频解码内部耗时、SD 独立延迟和双核实际负载仍需实机分析。
- 并发请求测试覆盖快速选择、取消、旧结果到达和 10000 次连续请求；最新帧访问及请求控制通过 ASan/UBSan 检查（未启用泄漏检测）。
- 默认与 USB＋OTA＋省电组合固件约 2.54/2.59 MiB；性能组合约 2.62 MiB，3 MiB OTA 槽余约 13%。精确大小以构建输出为准。
- 验证边界：主机测试不能证明真实 SD、I2S、SPI DMA 时序、面板帧率、长时间音画同步或功耗。中低优先级项保留待办。

实现与统计字段说明见 [IDF 视频播放器](idf-video-player.md)。
