# PN532 与桌面端

PN532 和 FRAM 共用 I2C：SDA GPIO1、SCL GPIO2；PN532 地址为 `0x24`，模块与 ESP32 共地并使用适合模块的 3.3 V 供电。模块需设置为 I2C 模式。总线和板型配置以 `src/config.h`、`components/board/` 为准。PN532 的 IRQ/RST 接法取决于实际板卡；若模块在复位中拉住总线，可能需要硬件复位或重新上电。

RSTPD 没有硬件上拉、或需要由固件显式复位时，可在 `menuconfig` 的 *StoryBox migration → PN532 RSTPD GPIO* 填该 GPIO；默认 `-1` 表示不驱动，行为与旧版一致。**legacy/V1 板的 IO48 是 NEXT 键，禁止填 48**（驱动会把它保持为输出高，按键失效）。2026-10-28 V2 原理图把 RSTPD 放在 IO48，按键已改到 TCA8418；确认实际板型后再启用，且只接独立 RSTPD 线。

原生实现位于 `components/nfc/`，产品入口在 `components/app/src/app.cpp`。`NativeNfc::Service` 独占一个 NFC 任务：`Pn532` 与 `Nfc` 的静态状态只在它上面读写，USB 路由把请求封送到该任务、等待执行完成后再取快照，因此协议 worker 不会和轮询或 I2C 事务竞争。USB 产品配置（`sdkconfig.usb-product`）通过 SBX4 v4 暴露与 Arduino 固件一致的动作：

| `act` | 请求字段 | 响应 |
| --- | --- | --- |
| `status` | - | `data.enabled/present/chip/fw/i2c/polling/busy/uptime/heap/card` |
| `poll` / `start` / `stop` | `on`（缺省 true） | 同 `status`；关闭 NFC 时返回 `NFC_DISABLED` |
| `refresh` | - | 重新寻卡，随后推送 `card` 事件 |
| `read` | `kind`=`page`/`block`、`start`、`count`、`key` | `data.kind/start/len/hex` |
| `write_ndef` | `ndef`（hex）、`verify`（缺省 true） | `accepted`、`len` |
| `write_raw` | `kind`、`start`、`data`（hex）、`key` | `accepted`、`len` |

寻卡周期由 `CONFIG_STORYBOX_NFC_POLL_MS` 配置，当前产品默认 **1000 ms**；改小可更快发现卡片，但会增加 RF/I2C 和功耗。设备设置页还有总开关“NFC 功能”，关闭后 `nfc.poll` 等动作返回 `NFC_DISABLED`，NFC 任务不再调用 `Nfc::loop()`，完全停止寻卡、模块探测和 I2C 访问；重新打开后服务会重新初始化 PN532。开关状态保存在 FRAM 的设置记录里（MPL6），也可由上位机用 `sys.set {"nfc":false}` / `{"nfc":true}` 修改并落盘。

错误码沿用旧固件：`NFC_UNAVAILABLE`（NFC 服务或共享 I2C 总线不可用；模块缺席时仍返回 `present:false`）、`NFC_DISABLED`（设备设置关闭了 NFC）、`NO_CARD`、`KIND`、`RANGE`、`AUTH`、`READ`、`READ_ONLY`、`TOO_LARGE`、`SIZE`、`TRAILER`、`BAD_KEY`、`BAD_HEX`、`BUSY` 等。

异步事件走同一 SBX4 通道，不带 `id`：`{"v":4,"evt":"nfc","type":"module"|"card"|"removed"|"write", ...}`。`card` 对象与 `status` 中的卡片字段一致（`uid/uidLen/atqa/sak/kind/type/std/type2/writable/formatted/cap/userStart/userPages/userTotal/userBytes/data/version/cc/lock/block0`）；`write` 事件带 `phase/pct/written/ok/code/msg`。`write_ndef`/`write_raw` 只在 NFC 任务接受任务时返回 `accepted`，实际分页写入与校验在后台推进，完成或失败由 `write` 事件报告。事件由应用任务入队、响应由 USB worker 入队，两者**可能乱序到达**；客户端应按事件类型处理，不能假定响应一定先到。

## 资源卡片写入流程

桌面端的写卡页只允许选择故事机 TF 卡上已经存在的资源，不再支持自由文本、URL 或自定义 NDEF。为避免重新遍历 SD 目录（大目录扫描可能超时），固件把启动时已经建立的媒体索引通过 `cmd:"media"` 分页暴露：

| `act` | 请求字段 | 响应 |
| --- | --- | --- |
| `info` | - | `data.ready/trackTotal/storyTotal/categories` |
| `tracks` | `offset`、`limit`（默认 12，最大 16） | `data.total/offset/limit/tracks`，每行 `[path, name, id, categoryIndex]` |
| `stories` | `offset`、`limit`（默认 8，最大 12） | `data.total/offset/limit/stories`，每行 `[audio, timeline, directory, category]` |

桌面同步后按音乐分类、故事分类展示可选资源；写入的 NDEF 是一条 URI 记录：

```text
storybox://media?path=/music/<分类>/<文件>.mp3
storybox://media?path=/story/<目录>/<音频>.mp3
```

卡片只保存路径，不复制媒体文件。资源被改名、移动或删除后卡片会失效，需要重新同步并重写。固件的媒体索引尚未建立时（新卡第一次上电、且还没有打开过音乐/故事列表），`media.info` 的 `ready` 为 false，桌面会提示先在设备上打开一次列表。

## 独立自动播放

NFC 开关打开时，设备启动即开始按 `CONFIG_STORYBOX_NFC_POLL_MS` 轮询，不依赖上位机。读到资源卡后固件解析第一条 URI 记录，取 `storybox://media?path=…` 的路径，在已加载的媒体目录里按完整路径匹配：

- 音乐：选中该曲目所在分类并 `Playlist::seekPath`，然后 `playCurrent(true)`。
- 故事：按 `Story.audio` 匹配后 `openStory(index)`，图文故事会进入故事页。
- 没有匹配项：只记一条 `NFC resource not in catalog` 日志，不播放。

为避免和桌面工作台抢控制，**最近 10 秒内收到过上位机命令时不自动播放**；桌面关闭、用充电器/移动电源供电或 USB 只供电时，10 秒窗口自然过期，放卡即播。自动播放和音量无关：当前音量若为 0，卡片仍会开始播放但听不到声音。当前卡片 NDEF 需在 256 字节用户缓存窗口内（本项目的资源 URI 远小于此），超长 URI 不会触发自动播放。

桌面端与 `tools/nfc_smoke_test.py` 必须连接 **USB 产品配置**（`sdkconfig.defaults` + `sdkconfig.usb-product`）。`sdkconfig.usb-diagnostics` 只注册文件路由，不注册产品 NFC 路由，`nfc.*` 会回 `UNSUPPORTED_FEATURE`。仓库内 `sdkconfig.usb-nfc-build` 额外打开 O3，用于本机 xtensa GCC 在 `-Og` 下编译 IDF `esp_lcd_panel_rgb.c` 触发 ICE 的情况：

```sh
idf.py -B build-usb-nfc -D SDKCONFIG=build-usb-nfc/sdkconfig \
  -D 'SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.usb-product;sdkconfig.usb-nfc-build' build
idf.py -B build-usb-nfc -p PORT flash
```

需要“无播放休眠”时，在默认配置串里追加 `;sdkconfig.power`；若 `build-usb-nfc/sdkconfig` 已存在，Kconfig 不会用 defaults 覆盖它，需删掉该文件或手动把 `CONFIG_STORYBOX_POWER_SLEEP` 改成 `y` 后重新构建。

桌面端位于 `desktop/`，包含演示模式和完整界面；真实设备可用功能以 hello 的 `features` 和固件响应为准。固件在 USB 产品配置下声明 `nfc`、`nfc.ndef`、`nfc.raw`、`nfc.write-verify`、`media`。开发命令见 [desktop/README.md](../desktop/README.md)，USB 文件操作见 [文件传输](file-transfer-refactor.md)。

快速冒烟：`python tools/nfc_smoke_test.py --port COM7`（加 `--text`/`--uri` 会先读卡再写 NDEF，加 `--read-pages 4,36` 会读取原始页）。冒烟脚本是诊断工具，仍可写任意 NDEF；产品桌面端的写卡页只允许资源卡片。验收时使用启用 USB 的产品固件，分别检查模块缺席、连接模块、放卡/移卡、原始读、NDEF 写入与校验，以及写入过程中移卡。实卡写入仍需要真机确认，静态构建与主机测试不能替代。已有板卡观察见 [真机验收记录](idf-acceptance-log.md)。
