# PN532 I2C 读卡能力与上位机协议

本文对应固件新增的 NXP PN532（I2C）支持，以及 `desktop/` 下的 Electron 上位机。目标是把“模块是否插入、卡片信息、写入内容”三件事做成一个稳定、可扩展的链路：

```text
PN532  <-- I2C -->  ESP32-S3 固件  <-- USB CDC / JSON -->  Electron 上位机
```

## 1. 硬件连接

PN532 与已有的 FRAM（MB85RC16）共用 I2C 总线：

| PN532 引脚 | 接到 ESP32-S3 | 说明 |
| --- | --- | --- |
| VCC | 3.3V | **不要接 5V**；模块和 ESP32 必须共地 |
| GND | GND | 必须共地 |
| SDA | IO1 | 与 FRAM SDA 并联 |
| SCL | IO2 | 与 FRAM SCL 并联 |
| IRQ | 可空 | 驱动通过 I2C RDY 字节轮询，不接也能工作 |
| RSTPDN | 可空 | 可接到空 GPIO，并在 `config.h` 设置 `PN532_RST_PIN` |

模块拨码（以丝印为准）通常为：

- **I2C 模式：SEL0 = ON，SEL1 = OFF**（有些模块标成 1=ON、2=OFF）
- HSU：SEL0 = OFF，SEL1 = OFF
- SPI：SEL0 = OFF，SEL1 = ON

I2C 地址固定为 **0x24**，与 FRAM 的 0x50 不冲突。总线默认 100 kHz（`PN532_I2C_HZ`），以兼容较弱的板载上拉；线短、上拉足够时可改 400 kHz。

> 如果模块没有板载上拉，请在 SDA/SCL 到 3.3V 之间各加 4.7k–10k 电阻。杜邦线尽量短，PN532 对电源和地线噪声比较敏感。

## 2. 固件结构

| 文件 | 作用 |
| --- | --- |
| `src/pn532.h/.cpp` | PN532 I2C 底层：命令帧/响应帧、ACK、RDY 轮询、寻卡、InDataExchange、Type 2 页读写、Classic 认证/块读写 |
| `src/nfc.h/.cpp` | NFC 业务层：模块状态、卡片建模、Type 2/Classic 差异、NDEF 写入状态机、事件队列、原始读写 |
| `src/hostlink.h/.cpp` | USB CDC 上的换行分隔 JSON 协议：上位机请求、事件推送、心跳与空闲停轮询 |
| `src/filexfer.h/.cpp` | TF 卡文件服务：目录列表、新建/删除/重命名、base64 分块读写、重新扫描媒体索引 |
| `src/config.h` | I2C 引脚、PN532 地址/速率、可选 IRQ/RST 引脚 |
| `src/main.cpp` | 启动时 `Nfc::begin()`，主循环里 `HostLink::loop()` |

### 启动与主循环

1. `Fram::begin()` 初始化 I2C 总线。
2. `Nfc::begin()` 探测 PN532：地址应答 → `GET_FIRMWARE_VERSION`；必要时用 `SAMConfiguration` 唤醒。
3. `HostLink::begin()` 输出一条 boot JSON（如果上位机已经打开串口就能直接识别）。
4. `loop()` 每轮调用 `HostLink::loop()`：
   - 驱动 `Nfc::loop()`：模块缺失时每 3.5s 重探；有模块时每 260ms 寻卡；写入时按页/块分步推进。
   - 把 NFC 事件序列化成 JSON 行。
   - 读取并处理上位机命令。

模块初始化失败不会阻塞音乐播放器启动；之后插入模块会被自动发现并上报。

### 卡片支持范围

- **Type 2**：NTAG210/212/213/215/216、MIFARE Ultralight。
  - 读取 UID、ATQA、SAK、GET_VERSION、CC、锁定位、用户区前 256 B。
  - GET_VERSION 的 storage size 映射：`0x0B`=NTAG210（48B）、`0x0E`=NTAG212（128B）、`0x0F`=NTAG213（144B）、`0x11`=NTAG215（504B）、`0x13`=NTAG216（888B）。
  - 写入标准 NDEF：自动写入 CC（未格式化时）、NDEF TLV、终止符 `0xFE`，按 4 B 页写入，可选逐页回读校验。
  - 原始 Page 读写（不允许覆盖配置页，限制在用户区）。
- **MIFARE Classic 1K / 4K / Mini**：
  - 读取 UID/ATQA/SAK；默认密钥 `FFFFFFFFFFFF` 认证后读取 Block 0。
  - 原始 Block 读写，支持传入 Key A；固件拒绝写扇区尾块（Trailer）。
  - 暂不支持 Classic 的 NDEF/MAD 写入。
- **ISO 14443-4**（如 DESFire）：仅识别 UID/ATQA/SAK，不做 APDU 读写。

卡片缓存最多 256 B 用户区；更大的 NDEF 内容可通过原始 Page 读取分段查看，但写卡容量以标签 CC/版本检测结果为准。

### NDEF 写入状态机

```text
startWriteNdef()
  ├─ 校验卡片：存在 / Type2 / 可写 / 容量
  ├─ 组装 TLV: 03 [len] <NDEF> FE + 0x00 填充
  ├─ 未格式化时先写 Page 3 的 CC: E1 10 <size> 00
  ├─ 每轮 loop 写一页 (4 B)，发送 progress 事件
  ├─ verify=true 时逐页回读比较
  └─ done / error 事件
```

写入过程中主循环只做一小步，所以屏幕刷新、按键和音频任务不会被长时间阻塞。写入期间请保持卡片稳定。

## 3. USB 串口协议（v2）

- 端口：ESP32-S3 原生 USB CDC（Windows 下通常显示为 `COMx`，厂商 `Espressif`）。
- 波特率：115200，8N1；USB CDC 实际速率不受波特率限制，但请保持一致。
- 编码：UTF-8，一行一个 JSON 对象，以 `\n` 结尾。
- 设备普通日志仍以 `[TAG]` 开头；上位机只解析以 `{` 开头的行。

### 3.1 握手

```json
{"v":2,"id":1,"cmd":"sys","act":"hello"}
```

设备返回：

```json
{
  "v": 2,
  "id": 1,
  "ok": true,
  "evt": "hello",
  "fw": "storybox-nfc-1.0",
  "proto": 2,
  "board": "ESP32-S3",
  "name": "StoryBox-3F2A",
  "role": "storybox",
  "features": ["nfc", "nfc.ndef", "nfc.raw", "nfc.write-verify", "fs", "fs.read", "fs.write", "fs.sd"],
  "nfc": {
    "present": true,
    "chip": "PN532",
    "fw": "1.6",
    "i2c": "0x24",
    "polling": false,
    "busy": false,
    "uptime": 18220,
    "heap": 219384
  }
}
```

设备启动时也会主动发一条 `{"evt":"boot", ...}`；上位机打开串口较晚时通过 `hello` 补握手即可。

### 3.2 模块与卡片状态

| 命令 | 说明 |
| --- | --- |
| `{"cmd":"nfc","act":"status"}` | 模块是否在线、轮询状态、当前卡片 |
| `{"cmd":"nfc","act":"poll","on":true}` | 启动轮询（默认关闭，由上位机开启） |
| `{"cmd":"nfc","act":"poll","on":false}` | 停止轮询 |
| `{"cmd":"nfc","act":"refresh"}` | 重新读取当前卡片并推送 card 事件 |
| `{"cmd":"sys","act":"ping"}` | 心跳；上位机每 5s 发一次 |

`status` 的响应在 `data` 中包含 `present/chip/fw/i2c/polling/busy/uptime/heap`，有卡时附带 `card`。

卡片对象示例：

```json
{
  "uid": "04A26B9E3C5180",
  "uidLen": 7,
  "atqa": "0044",
  "sak": "00",
  "kind": "ntag213",
  "type": "NTAG213",
  "std": "ISO 14443A · Type 2",
  "type2": true,
  "writable": true,
  "formatted": true,
  "cap": 144,
  "userStart": 4,
  "userPages": 36,
  "userTotal": 144,
  "userBytes": 144,
  "version": "0004040201000F03",
  "cc": "E1101200",
  "lock": "0000",
  "data": "030F...FE00..."
}
```

`data` 是 Type 2 用户区（从 Page 4 开始）的前 256 B 十六进制；NDEF TLV 在这个区域里。

### 3.3 读取原始数据

```json
{"v":2,"id":8,"cmd":"nfc","act":"read","kind":"page","start":0,"count":16}
```

- Type 2：`kind:"page"`，`count` 最多 64；一次读 4 页，返回 `count*4` 字节。
- Classic：`kind:"block"`，`count` 最多 16；可带 `"key":"FFFFFFFFFFFF"`（Key A）。不传时默认全 F。

响应：

```json
{
  "v": 2,
  "id": 8,
  "ok": true,
  "cmd": "nfc",
  "act": "read",
  "data": {"kind":"page","start":0,"len":64,"hex":"04A26B..."}
}
```

### 3.4 写入 NDEF

上位机负责把文本/链接编码成 NDEF 消息，再把消息的**原始字节**交给固件；固件负责 Type 2 TLV、CC、分页和校验。

```json
{"v":2,"id":9,"cmd":"nfc","act":"write_ndef","ndef":"D1010F540268...","verify":true}
```

- `ndef`：完整 NDEF 消息的十六进制，最大 888 B（取决于标签）。
- `verify`：是否逐页回读校验，默认 true。
- 立即响应 `{"ok":true,"accepted":true,"len":...}`，随后推送 `write` 事件：

```json
{"v":2,"evt":"nfc","type":"write","phase":"writing","pct":42,"written":60,"ok":true}
{"v":2,"evt":"nfc","type":"write","phase":"verifying","pct":96,"written":144,"ok":true}
{"v":2,"evt":"nfc","type":"write","phase":"done","pct":100,"written":144,"ok":true}
{"v":2,"evt":"nfc","type":"write","phase":"error","code":"VERIFY","msg":"回读内容与写入不一致"}
```

### 3.5 写入原始页 / 块

```json
{"v":2,"id":10,"cmd":"nfc","act":"write_raw","kind":"page","start":4,"data":"01020304"}
{"v":2,"id":11,"cmd":"nfc","act":"write_raw","kind":"block","start":1,"data":"00112233445566778899AABBCCDDEEFF","key":"FFFFFFFFFFFF"}
```

- Type 2 只能写用户区（Page >= 4），长度必须为 4 的倍数。
- Classic 长度必须为 16 的倍数；固件会拒绝 Trailer 块。
- 同样返回 accepted + `write` 事件。

### 3.6 事件

| `type` | 触发 | 字段 |
| --- | --- | --- |
| `module` | PN532 插入/拔出/重新探测 | `present/chip/fw/i2c/polling` |
| `card` | 新卡或刷新卡片 | `card` 对象 |
| `removed` | 卡片离开射频场 | — |
| `write` | 写入进度/结果 | `phase/pct/written/ok/code/msg` |

### 3.7 错误码

| 错误码 | 含义 |
| --- | --- |
| `NO_CARD` | 当前没有卡片 |
| `UNSUPPORTED` / `KIND` | 当前卡片类型不支持该操作 |
| `READ_ONLY` | 标签被锁定或 CC 标记只读 |
| `TOO_LARGE` / `SIZE` | 内容超过标签容量或长度不合法 |
| `RANGE` | 页/块地址越界 |
| `TRAILER` | 试图写 Classic 扇区尾块 |
| `AUTH` | Classic 密钥认证失败 |
| `READ` / `WRITE` | PN532 读写失败 |
| `VERIFY` | 回读校验不一致 |
| `CARD_GONE` | 写入过程中卡片离开 |
| `BUSY` | 上一次写入尚未结束 |
| `BAD_HEX` / `BAD_KEY` | 上位机参数格式错误 |
| `NO_CAPACITY` | 无法确定标签容量 |

### 3.8 TF 卡文件管理（fs）

文件管理器通过同一串口 JSON 协议访问 TF 卡。固件只接受 `/` 开头的绝对路径，拒绝 `..`、相对路径和空路径；内容用 **base64 + 4096 字节分块**传输，单行 JSON 上限 12KB，响应上限 16KB。

| 请求 | 作用 |
| --- | --- |
| `{"cmd":"fs","act":"list","path":"/","offset":0,"limit":64}` | 分页列目录，返回 `entries/total/capacity/used/free/ready` |
| `{"cmd":"fs","act":"mkdir","path":"/music/新文件夹"}` | 新建文件夹 |
| `{"cmd":"fs","act":"remove","path":"/music/old.mp3"}` | 删除文件或递归删除文件夹 |
| `{"cmd":"fs","act":"rename","from":"/a","to":"/b"}` | 重命名/移动 |
| `{"cmd":"fs","act":"read_begin","path":"/music/a.mp3"}` | 开始下载，返回 `xid/size/chunk` |
| `{"cmd":"fs","act":"read_chunk","xid":1,"offset":0}` | 读取一块，返回 base64 `data/eof` |
| `{"cmd":"fs","act":"read_end","xid":1}` | 结束下载 |
| `{"cmd":"fs","act":"write_begin","path":"/music/a.mp3","size":12345,"overwrite":true}` | 开始上传 |
| `{"cmd":"fs","act":"write_chunk","xid":2,"offset":0,"data":"<base64>"}` | 写入一块（4KB 原始数据） |
| `{"cmd":"fs","act":"write_end","xid":2}` | 结束上传并返回实际 `size/complete` |
| `{"cmd":"fs","act":"cancel","xid":2}` | 取消传输，删除未完成文件 |
| `{"cmd":"fs","act":"rescan"}` | 重新扫描 `/music` 媒体索引 |

示例：

```json
{"v":2,"id":20,"cmd":"fs","act":"list","path":"/music","offset":0,"limit":64}
{"v":2,"id":20,"ok":true,"cmd":"fs","act":"list","data":{"path":"/music","total":3,"capacity":31914983424,"used":10000000,"free":31904983424,"ready":true,"entries":[{"name":"月亮邮递员.mp3","path":"/music/月亮邮递员.mp3","dir":false,"size":4200000,"mtime":1760000000}]}}
```

文件管理错误码：`NO_SD`、`NOT_FOUND`、`NOT_DIR`、`IS_DIR`、`EXISTS`、`BAD_PATH`、`BAD_XFER`、`BAD_BASE64`、`READ_ONLY`、`AUDIO_BUSY`、`NO_SPACE`、`TOO_LARGE`、`IO`。文件写/删前固件会先停止播放并等待音频任务释放 SD 卡，避免和播放器并发访问 FATFS。

## 4. 上位机

上位机位于 `desktop/`，使用 Electron + React + TypeScript：

```powershell
cd desktop
npm install
npm run dev
```

演示模式（无需硬件）：

```powershell
$env:NFC_DEMO = "1"; npm run dev
```

打包：

```powershell
npm run build
npm run dist
# 产物: desktop/dist/StoryBox-NFC-Studio-Setup-1.0.0.exe（NSIS 安装包）
```

功能：

- **概览**：模块状态、实时卡片、快捷写卡、最近活动。
- **读卡器**：UID/ATQA/SAK/容量/NDEF/原始数据分页查看，支持导出 JSON。
- **写卡**：文本、链接、自定义 NDEF；容量校验、写入进度、回读校验；高级原始页/块写入。
- **卡片库**：本机快照、搜索筛选、JSON 导出。
- **文件**：Windows 资源管理器风格；浏览 TF 卡、拖放/粘贴上传文件或文件夹、下载、新建文件夹、重命名和删除；复选框多选、批量移动和拖拽移动；上传/下载显示传输进度，移动/删除显示任务进度。
- **设备与连接**：串口扫描/选择、PN532 状态、排查清单、实时日志、协议速览。
- **扩展中心**：传输/协议/能力/界面的分层说明和后续模块规划。
- **设置**：主题、自动连接、提示音、卡片库、演示模式、恢复默认。

数据目录：`%APPDATA%\StoryBox-NFC-Studio`。如果该目录被安全软件限制，可设置：

```powershell
$env:NFC_USER_DATA_DIR = "D:\StoryBoxData"
npm run dev
```

## 6. 排查

| 现象 | 排查 |
| --- | --- |
| 未检测到 PN532 | 3.3V 供电、共地、SDA/SCL 是否与 FRAM 并联、拨码是否 I2C、模块上拉、I2C 线长 |
| 串口连不上 | 关闭 Arduino 串口监视器/其它上位机；确认 USB 线支持数据；重新插拔 |
| 能看到串口但 hello 超时 | 确认固件为带 `hostlink.cpp` 的版本；115200 8N1；换 USB 口 |
| 能寻卡但读取失败 | 卡片是否为 Type 2；PN532 天线附近是否有金属；尝试缩短连线或降低 I2C 速率 |
| 写入 `READ_ONLY` | 标签静态锁定位已置位或 CC 只读；换一张可写标签 |
| 写入 `VERIFY` | 卡片中途移动、供电不稳、标签质量差；重试并保持卡片不动 |
| 写入 `AUTH`（Classic） | 密钥不是全 F；在上位机高级写入中传入正确 Key A |
| 卡容量显示偏小 | CC 容量可能小于物理用户区（例如 NTAG215 的 CC 0x3E），固件按 CC 限制 NDEF 写入 |

## 7. 已知限制

- 只做 ISO 14443A；不支持 14443B、FeliCa、DESFire APDU。
- Classic 只支持原始块读写，不支持 NDEF/MAD。
- Type 2 首次卡片读取缓存前 256 B；更大的 NDEF 需要在上位机里用原始读取分段查看。
- 单目标寻卡（`InListPassiveTarget` 只请求 1 张卡）。
- I2C 与 FRAM 共用总线，所有 NFC 操作都在主循环串行执行，不会与音频任务并发。
- 写入期间不响应新的 NFC 命令，但 UI 仍会收到进度事件。
