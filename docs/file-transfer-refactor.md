# 文件传输重构：兼容协议阶段

本阶段解决主循环阻塞、单块等待和传输期间资源争用。仍使用 USB CDC JSON v2 / Base64，尚未引入二进制分帧、独立存储任务或跨重启续传。没有实机吞吐量结论。

## 会话与兼容

固件 hello/boot 新增 `fs.session` 和 `fs.window4.crc32` 能力。

- `fs.session_begin`：整批上传或一次下载前取得占用，等待音频关闭文件句柄。已有传输或 NFC 写卡时拒绝。
- `fs.session_end`：没有未结束文件时释放占用。
- 旧固件不声明能力时，上位机继续单块串行传输，不发送新会话命令。
- 新固件仍支持旧客户端，单文件活动期间自动保护；文件结束后释放。
- 会话 60 秒没有文件命令时取消，USB 断开或设备长按 OK 也会清理。取消整批会话后拒绝后续分块/文件，直到上位机结束会话或显式开始新的会话。

占用期间停止播放，播放器执行端也拒绝已排队的播放命令。实体播放操作被传输界面接管，BLE 播放控制返回 `TRANSFER_BUSY`，USB NFC 命令也返回该错误。NFC 轮询和异常重探测被跳过，保留原轮询开关状态，释放后继续。禁止自动休眠，进度条最多每 250ms 更新一次。结束后回主页，不自动恢复播放。

## 数据路径

固件串口读取由每轮 512 字节改为最多 24 KiB / 约 6ms 的收包预算（同步写盘时间不受该预算约束）。每个块仍为 4 KiB；桌面端协商后最多四块并行，按窗口等待完成后推进。单窗口 Base64 请求约 22 KiB，低于固件 32 KiB 接收队列。

上传块可携带 IEEE CRC32，固件解码后验证；下载块返回 CRC32，支持新能力时上位机要求校验值存在，并检查偏移与长度。发生失败时等待该窗口在途请求全部结束，再执行清理，避免取消与后续写入交叉。确认进度必须来自设备，不能在响应不足时虚构成功。USB 保序，缺块导致后续偏移不连续时会失败，尚未实现选择性重传窗口。

继续使用固件已有的 16 KiB 合并写入。新会话中每个文件结束不再读取容量信息；批次结束再扫描索引。下载顺序读取避免不必要的 seek。

## 文件完整性

设备上传先写同目录 `.storybox-upload-*.part`，完成后核对已接收大小和文件大小，再提交。覆盖时将旧文件改名为对应 `.bak`，提交失败尝试恢复原名；无法恢复时保留备份供人工恢复。取消删除临时文件，不删除原目标。FAT 上的多个改名步骤不是断电原子事务；断电恢复和完整文件落盘回读校验尚未实现。

本机下载也先写唯一临时文件，完整接收后再改名；错误清理仅删除本次创建的临时文件。

## 实机验收

固件与桌面端一起更新，使用同一张 TF 卡和同一份大文件比较前后速度。上位机日志新增：平均 KiB/s、总耗时、SD write 累计耗时和单次最长耗时（不包括最终 flush/rename 的单独统计）。

建议依次检查：大文件双向传输与 SHA256 对比；大量小文件；NFC 无卡和异常模块；传输中按键/BLE 播放；长按 OK；拔 USB；卡满；覆盖文件失败。尚未连接实体硬件，以上用例需要实机执行。

自动验证覆盖桌面端窗口并发、旧固件回退、错误确认、下载校验、在途请求清理和会话门禁；C++ 与 TypeScript 使用相同 CRC 标准向量。固件使用临时 ESP32 平台 6.12.0 / Arduino 2.0.17 配置编译。
