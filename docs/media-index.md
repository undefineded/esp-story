# SD 卡媒体索引

首次启动没有有效索引时，扫描 `/music` 和 `/story` 并写入 SD 卡根目录的
`/.esp-story-index.bin`。之后启动只读索引；分类切换、进入故事列表都使用
内存数据。打开故事直接读取索引指定的音频和 LRC 路径，不再枚举目录。
LRC 内容在打开故事时解析，JPEG/MP3 在播放时按需读取。

增删或重命名媒体后，从主页进入“设置”，用 NEXT/LAST 选择第四项
“刷新列表”，单击 OK 执行。旋转旋钮不会触发扫描。刷新会停止播放，显示
扫描提示，并同时更新音乐分类、曲目、故事目录、故事音频和时间轴路径。
完成后留在设置页显示结果，双击 OK 保存并回主页。设置现在只能从主页进入；
空列表也不会阻止刷新。

索引是程序维护的二进制文件，不需要手工编辑。格式包含魔数、版本、数量、
UTF-8 字符串长度及 FNV-1a 校验值；加载时检查长度、数量、路径和校验值。
字段最长 511 字节。刷新先写 `.tmp` 并关闭、回读校验，然后以 `.bak` 保留
上一代索引，再重命名临时文件。启动优先读取主索引，其次读取有效备份；
两者都无效才重新扫描。备份恢复可能显示上一代列表，可手动刷新至最新状态。
这些措施不能保证 FAT 文件系统在突然断电时不损坏。

写入失败时保留当前扫描出的内存列表并显示“索引保存失败”；下次重启可能
使用旧索引。扫描失败时尽量恢复上次有效索引，不发布不完整的新索引。
添加/删除媒体不会自动使有效索引失效，文件不存在时需手动刷新。
换卡请关机后操作；索引随卡保存，不复用另一张卡的列表。

保留现有容量限制：最多 300 首音乐、32 个音乐分类（另加“全部歌曲”）、
32 个故事，每个故事最多 256 幅插画。达到列表上限时刷新结果会提示；
本次没有增加动态分页或突破这些限制。目录扫描仍是同步操作，手动刷新期间
暂不接受正常播放操作；日常启动和页面切换不再做全量扫描。

## 验证

```sh
g++ -std=c++11 -Wall -Wextra -pedantic -fsanitize=address,undefined \
  -Itest/catalog_host -Isrc src/catalog.cpp test/catalog_host/test_catalog.cpp \
  -o /tmp/esp-story-catalog-test
/tmp/esp-story-catalog-test
```

此测试使用生产 `catalog.cpp` 和编解码器，模拟 SD 文件系统及音乐/故事目录
数据，验证缓存启动、刷新、损坏校验、空卡、写入失败、替换中断和备份恢复。
实际目录扫描、FAT 行为和音频停止确认需在硬件上验证。

实机步骤：首次启动检查 `[INDEX] refreshed`；再次开机检查 `[INDEX] loaded`；
增加/删除文件后确认列表保持不变，执行刷新后确认更新；播放中刷新检查音频
停止，退出设置后能选新曲目；测试空卡、索引损坏、两种旋转方向下的主页四个图标和内部列表。
