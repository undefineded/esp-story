# Video V2 文件转码工具设计

本文是待实现工具的需求与实现约定，配套总体方案见 `README.md`。下文的 `build_video_v2.mjs` 和 `verify_video_v2.mjs` 均为拟定名称，当前尚不存在，命令不能直接使用。

## 工具职责与依赖

工具在电脑上将常见视频转换为设备专用 `.sv2` 文件和同名独立 MP3。优先降低设备的读取、像素处理与推屏耗时，默认输出 320×240、20fps，另支持 15fps。

- Node.js：启动子进程、组帧、差分编码、文件写入和校验。
- ffmpeg：解码素材、缩放、调帧率、输出 RGB565 及转码音频。
- ffprobe：获取视频、音频流及时间戳信息。
- 第一版不依赖 Python，也不实现 LZ4；现有 AVI/QOI 工具不承担 `.sv2` 编码。

启动时检查依赖是否可执行，并检查 ffmpeg 支持 `rgb565be` 和 `libmp3lame`。路径以子进程参数数组传入，不拼接 shell 命令，兼容中文、空格和特殊字符。

## 拟定命令接口

```bash
# 默认：20fps、320×240、等比补黑边、有音轨则提取
node tools/build_video_v2.mjs input.mp4 --out out-video-v2

# 15fps 档位
node tools/build_video_v2.mjs input.mp4 --fps 15 --out out-video-v2

# 裁切填满、只转换指定片段
node tools/build_video_v2.mjs input.mp4 --fit crop --start 00:01:00 --duration 30

# 批量处理目录，默认不递归
node tools/build_video_v2.mjs --all-in ./sources --out ./out-video-v2

# 独立校验已有产物
node tools/verify_video_v2.mjs ./out-video-v2
```

| 参数 | 默认值 | 约定 |
| --- | --- | --- |
| 输入路径 | 必填，或使用 `--all-in` | 支持一个或多个文件 |
| `--out` | `out-video-v2` | 输出目录 |
| `--fps` | `20` | 首版仅接受 `15` 或 `20`，格式头仍用分数表示帧率 |
| `--fit` | `pad` | `pad` 等比补黑边；`crop` 等比裁切填满 |
| `--keyframe-ms` | `1000` | 最大关键帧时间间隔，必须大于零；编码时换算成至少一帧 |
| `--audio` | `auto` | `auto` 有音轨则输出；`none` 不输出音轨 |
| `--start` | `0` | 非负秒数或 `HH:MM:SS[.毫秒]` |
| `--duration` | 剩余时长 | 必须大于零，音视频使用同一截取区间 |
| `--all-in` | 不启用 | 扫描指定目录，按稳定顺序处理支持的文件 |
| `--overwrite` | 不启用 | 明确允许替换同名输出 |
| `--help` | 不启用 | 显示用法及依赖信息 |

首版固定 320×240、16×16 分块、RGB565，不开放未经固件验证的任意尺寸与像素格式参数。关键帧周期属于高级参数；工具应提示过短周期带来的读取开销。

## 输出目录与命名

```text
out-video-v2/
  示例.sv2          # 放入 TF 卡的主视频文件
  示例.mp3          # 可选，必须与视频同名前缀
  示例.report.json  # 转码统计，供电脑分析，不要求拷入 TF 卡
```

设备目录约定由 V2 固件最终确定；在固件实现前不要求旧播放器识别这些文件。

输出前检查所有输入的目标文件名冲突，包括不同目录的同名文件和大小写差异。默认报错，不静默覆盖。不要把原始帧流保存在最终输出目录。

## 转码流水线

### 1. 探测与时间轴规划

使用 ffprobe JSON 输出读取流信息，默认选择第一个非封面视频流和默认音轨，缺少默认音轨时选择第一条音轨。没有有效视频流时失败。

统一计算截取起点、视频开始时间和音频相对偏移，再生成两路 ffmpeg 参数。保留相对偏移：迟到音轨补静音，提前的音轨裁掉超出部分；不能简单将音视频各自独立归零而丢失原有偏移。

音轨结束早于视频时，默认补静音至视频结束；晚于视频时裁切。MP3 编码延迟与填充是否被设备解码器处理，需要真机验证，并在报告中记录已知限制。

视频变成恒定帧率后，以实际输出帧数计算最终时长，而非直接相信源文件声明时长。末帧补齐及音轨裁切的误差应控制在一个输出帧周期以内。

### 2. ffmpeg 输出 RGB565

等比补边的核心参数如下；正式工具还需加上流选择、时间轴和截取参数：

```bash
ffmpeg -i input.mp4 -an \
  -vf "fps=20,scale=320:240:force_original_aspect_ratio=decrease,pad=320:240:(ow-iw)/2:(oh-ih)/2" \
  -pix_fmt rgb565be -f rawvideo pipe:1
```

裁切模式改用等比放大后居中裁切：

```text
fps=20,scale=320:240:force_original_aspect_ratio=increase,crop=320:240
```

第一版关闭会引入额外帧间像素波动的量化抖动；实现时显式验证 ffmpeg 的 RGB565 转换设置及颜色结果。RGB565 大端字节序必须通过设备色条测试后确认。

每帧严格为 `320 × 240 × 2 = 153600` 字节。Node.js 的 stdout 数据块不等于视频帧：组帧器必须处理一帧跨多个块、一个块包含多帧等情况。流结束后若有不足一帧的剩余数据，应报错。

持续读取 stderr，避免子进程因管道写满而阻塞；保留有界错误日志。文件写入使用背压控制，内存占用不随视频长度增长。

### 3. 差分编码

编码器持有前一帧和当前帧，以及有限大小的写入缓冲：

1. 第一帧和达到关键帧周期的帧输出完整画面。
2. 其余帧按 16×16 块比较 RGB565 字节，任意像素不同就标记整块变化。
3. 先合并同一块行内连续变化块；再纵向合并左右边界相同的相邻矩形。
4. 按从上到下、从左到右的稳定顺序写矩形，载荷为每个矩形逐行紧密排列的最终像素。
5. 完全相同时输出空更新帧；关键帧周期到达时仍按关键帧规则处理。
6. 差分总记录长度不小于关键帧记录，或矩形数量超过格式限制时，输出关键帧。
7. 每一帧都推进帧序号，帧时间由序号和帧率计算，不因空帧缩短时长。

首版不合并跨越未变化块的矩形，避免为减少命令数显著放大载荷。后续可按真机 SPI 调用开销评估此类合并。

比较发生在 RGB565 量化之后，不用 RGB888 源像素判断差异。第一版保持 RGB565 帧逐像素一致，不引入变化阈值、主动丢帧或有损去噪。

### 4. 写文件与索引

- 临时文件中预留文件头，顺序写帧记录，末尾写索引，完成后回填头部。
- 每帧索引包含偏移、长度和类型；逐项写入临时索引文件或分段缓冲，避免为长片保留无限数组。
- 元数据用显式小端读写，64 位文件偏移在 Node.js 中使用 BigInt，并确认文件 API 对大偏移的支持。
- CRC 算法及覆盖字节范围必须在正式格式文档中唯一确定，并提供固定测试向量；未固化前不宣称生成版本 1 兼容文件。
- 主文件大小接近 FAT32 单文件上限时必须提前报错。首版不自动切片，因为切片还需要固件的跨文件播放协议。

正式编码前应先形成逐字节的格式规范，工具与固件共同遵守总体方案中的长度、坐标、偏移和溢出检查。

### 5. 提取音频与发布产物

音频默认单声道、22.05kHz、48kbps MP3，与当前音频链路保持一致。视频、音频、报告先在输出目录下唯一的临时子目录生成，成功校验后再发布。

默认目标已存在则失败。指定 `--overwrite` 时，先备份原有同名产物，再替换整组文件，出错则尝试恢复；多文件重命名不是天然原子事务，需保留可识别的恢复状态。

当新视频无音轨或设置 `--audio none` 时，只有在允许覆盖且新产物成功后，才移除属于同一输出组的旧 MP3，不能误用旧音轨。中断或失败时不把半成品命名为最终文件。

## 转码统计与性能报告

报告至少包含：

| 类别 | 字段 |
| --- | --- |
| 基础信息 | 工具/格式/ffmpeg 版本、有效参数、尺寸、帧率、实际帧数、时长、像素字节序 |
| 编码结果 | 关键帧、差分帧、空帧数量，矩形数分布，变化像素比例 |
| 数据量 | 总大小，帧记录大小 P50/P95/P99/最大值，平均及滑动窗口峰值读取量 |
| 推屏预算 | 每帧更新像素字节数及矩形数，40/80MHz 下像素传输的理论耗时 |
| 音频 | 是否存在、输出参数、时间偏移处理、文件大小、已知编码延迟限制 |
| 校验 | 结构校验、CRC、逐帧像素比较的结果与是否实际执行 |
| 告警 | 整帧退化比例、峰值数据过大、超过目标设备能力或文件大小限制 |

建议以 100ms 和 1s 滑动窗口统计包含帧记录开销的视频读取量，音频开销单独列出。索引读取、文件系统开销和读卡延迟另行考虑，不把理论估算当成真机吞吐量。

示例结论应表达为“峰值读取量需要设备验证”，不能只根据平均变化比例标记“保证 20fps”。15fps 与 20fps 应独立转码、独立报告，不能仅修改文件头帧率。

## 校验工具

构建工具默认执行结构、CRC 和逐帧 RGB565 比较。编码时把每帧源 RGB565 的 SHA-256 顺序写入临时校验文件；完成后用独立解析路径恢复每帧并比对摘要，避免在内存中保留整个视频。摘要文件仅用于构建校验，不是设备格式的一部分。

独立 `verify_video_v2.mjs` 可以检查已有产物的结构、CRC、索引、帧依赖与可重建性；没有源帧或参考摘要时，不能声称已验证它与源视频像素一致。

必须拒绝以下文件：

- magic、版本、像素格式或帧类型不受支持。
- 首帧不是关键帧，帧序号不连续，索引和实际记录不一致。
- 矩形越界、长度不匹配、整数溢出或记录超出文件范围。
- 文件截断、CRC 错误、帧数与实际记录数量不符。
- 不符合目标固件尺寸或资源上限的文件。

## 错误处理与退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 所有输入转换并校验成功；性能提示可以存在 |
| `1` | 一个或多个转换、写入或校验失败 |
| `2` | 参数错误、依赖缺失、输出冲突等前置检查失败 |
| `130` | 用户中断 |

批处理采用串行转换以控制 CPU 和内存，单个文件失败后继续处理其他文件，最后汇总失败项并返回非零退出码。发生中断时结束 ffmpeg 子进程并清理本次临时文件，不影响已完成输出。

日志区分探测、视频编码、音频处理、校验和发布阶段；进度以实际处理帧数为准，源时长未知时不显示虚假的百分比。

## 建议代码组织与开发顺序

以下为拟定路径：

```text
tools/build_video_v2.mjs       命令行与转换流程
tools/verify_video_v2.mjs      独立文件校验入口
tools/lib/video-v2-format.mjs  格式常量、边界与元数据编解码
tools/lib/video-v2-encoder.mjs 分块比较、矩形合并、帧类型选择
tools/lib/video-v2-reader.mjs 索引解析与画面重建
tools/selftest_video_v2.mjs    主机端格式与转码自测
```

先固化格式并用人工构造帧完成编码/恢复往返，再接入 ffmpeg 流式输出，最后实现音轨对齐、统计、批处理和覆盖恢复。

测试至少覆盖：纯色、静态帧、单块变化、跨块边缘变化、整屏变化、空帧、关键帧切换、无音轨、音轨晚起播、可变帧率输入、半帧输入、错误索引、损坏记录、中文路径与输出冲突。Windows 与 Linux 均验证子进程参数和文件发布行为。

完成工具只表示可以生成并校验文件；稳定 15～20fps 仍需配套 V2 固件及真机验收。
